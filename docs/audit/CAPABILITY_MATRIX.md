## Status words

From section 2 of `docs/roadmap/NEXUS_WORLD_CLASS_ROADMAP.md`, made precise for single rows:

- **REAL**: works, and a named test proves it. The first REAL rows came with L1 T3: sign-in, sign-out, the me route and context switching. Elsewhere the tests that call routes prove labeling and refusal, not that a capability works.
- **PARTIAL**: part of the claimed behavior exists.
- **SIMULATED**: returns invented results as if they were real.
- **BROKEN**: unsafe or wrong. It reads or changes another org's data, exposes secrets, forges records, or accepts what it must refuse. A route that is both BROKEN and SIMULATED is listed as BROKEN, and its evidence says both.
- **UNVERIFIED**: looks correct when read; nothing has checked it.

**Known by**: `read` means the whole handler was read on 2026-10-25; `searched` means the file was searched for API calls and fixed figures but not read in full; `test: <name>` names a test in `npm test` that checks the row; for a SIMULATED row that is the claim that it answers only in demo mode and says so.

**True of every row, so not repeated below.** Since L1 T3 identity comes from the session on each request (`server.ts#res.locals.userId = user.id;`), and every route except sign-in and deployment calls answers 401 without one (`server.ts#if (!found || !user) return res.status(401).json({ error: 'Sign in required.' });`); before that, every route trusted whoever the last request's headers claimed to be. Which org's records a route may touch is L1 T4. Since L1 T5 every changing route checks the caller's role against one table (`server/permissions.ts#export const PERMISSIONS: Record<string, Role[]> = {`). Every write goes through one store: since L1 T10 a SQLite transaction holding only the records that changed (`server/storage.ts#this.sql.exec('BEGIN IMMEDIATE');`), with ids that do not collide (S27). L0 T4 and L1 own these.
